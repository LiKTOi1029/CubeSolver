### 2026/9/12
I tried doing a few new things, however I quickly realized that the strategy I was using was flawed from the 
ground up to code a cube's moveset. You see, my code saw a single side of the cube like this
```lua
local Type = "3X3"
local Cube = {"W","W","W","W","+","W","W","W","W","B","B","B","B","+","B","B","B","B","O","O","O","O","+","O","O","O","O","G","G","G","G","+","G","G","G","G","R","R","R","R","+","R","R","R","R","Y","Y","Y","Y","+","Y","Y","Y","Y"}
```
Which was stored into a variable that was provided by a file named `status.lua` (I have already removed this 
at the time of writing this). This said variable then was accessed by the rest of the application to allow 
several command files found in `data/commands/...` to interact independently of one another, yet simultaneously 
use the `status.lua` file together as though they were one working, cohesive function. The issues with this are 
obvious for the given context. That being the prevelant desynchronization issues that I faced while coding this.\
\
Fun fact, when you use multiple local instances of a single file-provided variable, it just so happens that the 
rest of the application will also use different local instances of the same file. This means multiple instances 
need to sync with one another. This is clearly inefficient considering it is in an offline environment and the 
parts of the code that need to be accessed by other parts of that same code shouldn't be this difficult or 
convoluted to access.\
\
Now, apart from this, the main 'cube' representation of the application was generated by another program file 
called `data/cubes/regular/3x3.lua` (the first one I made for the 3x3, standard rubik's cube) generates every 
single side of the cube as 9 individual faces, the `"+"` signs being the centers and thus no need to be counted. 
(oh what a mistake THIS move right here was) and instead I used a script with hardcoded positions to move each 
related face corresponding with the move played. In the code's internal system, the white side is up and the blue 
side is facing the front. This means that a `U` turn would result in the `Blue` side to go into certain tiles 
of the `White` side, the `White` side into certain tiles of the `Green`, the `Green` tiles to go into certain 
tiles of the `Yellow` side, the `Yellow` side to go into certain tiles of the `Blue` side, and finally for the 
`Orange` side to complete a full 90 degree, clockwise turn. All moves turn exactly one of the sides clockwise by 
90 degrees. This is guaranteed for every single available move on the cube.\
\
The problem with this hardcoded solution is that we are not working with 6 separate sides divided into 9 totally 
unrelated, disconnected faces. We are working with a three dimensional object that likewise must turn as a 
three dimensional object would. I would hardcode all of the correct positional swaps on the two dimensional, 
disconnected sides-and-faces cube and yet it wouldn't work. The reason why is because none of the faces are 
disconnected as the code representation up top shows. They are connected, in fact the only 'disconnected' pieces 
are the 6 center pieces. They have no other colors besides the color of each of their corresponding sides. 
Meanwhile, edge pieces have 2 colors per piece and corner pieces have 3 colors per piece. All this to say, there 
are actually 20 moving pieces on the entire 3x3 cube. 8 pieces on the top layer, 4 edge pieces on the middle 
layer, and 8 more pieces on the bottom layer $8+4+8=20$\
\
Which leads us to a new solution. I am going to *actually use three dimensional cubes and movesets* instead of 
taking the easy-looking way out that is actually the impossible way (two dimensional, disconnected sides-and-faces) 
but actually do it properly and use three dimensional cubes internally. This way, the cube will *actually turn as intended* 
something which I had not even thought of yesterday. This also means a lot of the code structure I built *must* 
change to accommodate for these changes. I might have to slightly extend the time limit so that I can stick to it 
since I did kind of shoot myself in the foot by not doing it properly. Anywho, now I am actually going to do it.
